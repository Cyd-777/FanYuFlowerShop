# 通知清单与双通道

> **所属**：[类OA通知模块](./类OA通知模块.md)  
> **状态**：规划 · **当前只做 §A 订单 + §B 库存**（无智库 / AI）

## 架构原则

| 通道 | 载体 |
|------|------|
| **App 内** | 消息面板 + Tab 角标（**仅**订单、库存等业务事件） |
| **App 外** | 微信服务通知（同事件双发，失败不阻断内通道） |

**不属于消息面板的内容** → 见下文「即时反馈 · 提示条」。

## 即时反馈 · 提示条（非消息面板）

随操作即时出现、无需入库、无需未读角标 — 用 **`AppFeedbackHost` 提示条**（或页面内 toast）：

| 场景 | 方式 | 不进消息面板 |
|------|------|----------------|
| 图片 / 文件上传失败 | 操作当场提示条 | ✓ |
| 表单保存失败 | 当场提示 | ✓ |
| 网络 / 云函数错误 | 当场提示 | ✓ |

消息面板只承载 **跨时间、可回看** 的业务事件（订单状态变更、库存预警等）。**日汇总 / pending 超时 / 滞销** 不进面板 — 见下文「不做 · 云端定时」。

## ~~不做 · 云端定时通知~~

| 原设想 | 不做理由 | 替代 |
|--------|----------|------|
| `order.pending_timeout` | 买卖需商家主动盯单；不占云端定时资源 | 下单即时 `order.new` + 角标；订单列表看 pending |
| `order.daily_summary` | 日结应订单累加计算，非推送 | 商家台/订单统计面板（按单实时累加） |
| `stock.slow_moving` | 无批次码，混放无法分批次；小店场景无意义 | 以后 **销售情况面板** 按商品展示销量 |

`scheduler` 云函数保留代码但 **不配置定时触发器**（`config.json` triggers 为空）。

## A · 订单通知（下一步实现）

与订单状态对齐（`pending` → `accepted` → `preparing` → … → `completed` / `cancelled`）。

### A 端（顾客）

| eventKey | 触发点 | 摘要示例 |
|----------|--------|----------|
| `order.created` | 创建成功 | 订单 #xxx 已提交，等待确认 |
| `order.accepted` | 商家接单 | 订单已被确认，正在准备 |
| `order.ready_pickup` | 自取 · `ready` | 已备好，请到店取货 |
| `order.delivering` | → `delivering` | 花束配送中 |
| `order.completed` | → `completed` | 订单已完成 |
| `order.cancelled` | → `cancelled` | 订单 #xxx 已取消 |
| ~~`order.pending_timeout`~~ | ~~定时~~ | **不做** — 见「不做 · 云端定时」 |

### B 端（商家）

| eventKey | 触发点 | 摘要示例 |
|----------|--------|----------|
| `order.new` | 创建成功 | 新订单！{昵称} {商品摘要} |
| ~~`order.pending_timeout`~~ | ~~定时~~ | **不做** |
| `order.cancelled` | 取消 | 订单 #xxx 已取消 |
| ~~`order.daily_summary`~~ | ~~每天 21:00~~ | **不做** — 改订单累加/面板 |
