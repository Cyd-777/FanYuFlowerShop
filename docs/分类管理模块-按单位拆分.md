# 按单位拆分

> **所属**：[分类管理模块](./分类管理模块.md)  
> **状态**：已定案（2026-06-30）

## 目的

减少商户手动维护，让商品分类尽可能从百科品种自动衍生，商户只需维护「非花材」的自定义分类。

## 策略

1. **商品单位决定分类来源**

   | 商品单位 | 分类来源 | 举例 |
   |---------|---------|------|
   | 支 / 组 | 百科品种自动衍生 | 玫瑰（支）、百合（组）→ 自动对应百科品种 |
   | 件 | 自定义分类（商户手动维护） | 包装纸、贺卡、玩偶、花瓶等物料 |
   | 束 | 自定义分类（商户手动维护） | 混搭花束、礼盒、花篮 |

2. **商户加花 → 只建百科词条** — 新品种：百科加词条 + 建商品选品种 → 分类自动匹配。

3. **选花即确定分类** — 不再文本匹配「猜」分类。

4. **自定义分类为未来留冗余** — 物料、花束类完全商户 CRUD。

5. **云端分类列表 = 衍生（只读）+ 自定义（可编辑）** — `listPublicCategories` 合并返回；B 端只显示自定义。

## 实施步骤

| 步骤 | 内容 | 涉及 |
|------|------|------|
| 1 | `listPublicCategories` 合并衍生 + 自定义 | cloudfunctions/category |
| 2 | 商品编辑页按单位锁定可选分类 | pagesMerchant/goods/edit |
| 3 | B 端分类管理只显示自定义分类 | pagesMerchant/category/ |
| 4 | 百科品种列表动态读取 | wiki / flower_wiki |
| 5 | 自定义分类保留 `customRole`（定制花束选材） | — |

## 影响范围

cloudfunctions/category、商品编辑页、分类管理页、百科品种读取。
