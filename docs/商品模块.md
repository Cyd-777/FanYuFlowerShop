# 商品模块

> **分层**：业务  
> **状态**：已迁入（源自 [待处理/goods.md](./待处理/goods.md)）

## 策略

商品模块覆盖**三环闭环第一环**：商家侧商品 / 分类 / 花材库维护，以及顾客从浏览到购物车管理的完整链路。

```text
商家上架 → 顾客浏览 → 详情 → 加购 → 购物车（勾选、改数量）
                                              ↓
                                    点击「结算」进入 [订单模块](./订单模块.md)
```

负责「想买什么」：快照价、库存校验、本地购物车持久化；不负责填单、成交及之后的一切。

**三环闭环（商品侧）**：商家 CRUD、上下架、可售数、批量操作、进货单加可售数、口语搜索（商家端）；顾客浏览、加购、购物车。0.2.0 改号前做**短回归**即可。

**闭环之后优化（不阻塞 0.2.0）**：分类按单位拆分、列表效率、文案（「库存」→「可售数量」）、顾客端热字段刷新 — 与搜索 / 智库可并行。第一阶段 CRUD / 批量 / 进货单 / 口语搜索**已够用**。

- **确认页填单**及之后的创建订单、支付、订单列表 / 详情、商家处理、核销 → [订单模块](./订单模块.md)
- **会员积分**、地址簿长期管理（地址选择在确认页，属订单流）→ [地址](./地址模块.md)、[会员体系](./会员体系模块.md)
- **花卉百科正文** → [智库模块](./智库模块.md)（商品详情仅链到百科卡片）
- **分类按单位自动拆分**等管理侧策略 → [分类管理](./分类管理模块.md)（与商品编辑联动，文档分模块写）

---

## 与订单模块的接口

| 时点 | 商品模块 | 订单模块 |
|------|----------|----------|
| 加购 / 改购物车 | 写入 `cart` store，含快照价、库存 | — |
| 点击「结算」 | 校验已勾选行，跳转确认页 | 确认页读取 `checkedItems` |
| 提交订单 | — | `order.create`、扣库存、清空已下单项 |
