# 版本与发版模块

> **分层**：工程  
> **状态**：已迁入策略

## 策略

定义**几.x 必须完成什么才改号**，以及闭环之后的推荐推进顺序，避免版本号与能力范围脱节。

### 版本线

| 阶段 | 目标 | 策略要点 |
|------|------|----------|
| **0.1.x（当前）** | 把微商**三环闭环**做稳 | 商家维护商品 → 顾客下单 → 商家履约；**不含**微信支付、会员 |
| **0.2.0** | 闭环验收通过才改号 | 见 [待处理/versions/0.2.0.md](../待处理/versions/0.2.0.md)；不挡改号项：支付、会员 |
| **0.2.x（闭环之后）** | 在闭环基础上**加固** | 搜索统一、智库升级、商品管理优化等 |
| **0.3.0 及以后** | 会员、优惠券等 | 见 [待处理/versions/0.3.0.md](../待处理/versions/0.3.0.md) |

### 闭环之后推荐优先级（与 Issue #1 对齐）

与 [待处理/post-closed-loop-branches.md](./待处理模块-post-closed-loop-branches.md) 一致：

1. 合并闭环分支，打 **0.2.0** 标签（短回归）。
2. **搜索 + 智库契约**（可与 0.2.x 小版本同行）→ [搜索](./搜索模块.md)、[智库](./智库模块.md)
3. **分类管理优化**（按单位自动拆分）→ [分类管理](./分类管理模块.md)
4. 商品递交方式（自提 / 配送）、商品管理体验优化 → [订单](./订单模块.md)、[商品](./商品模块.md)
5. 会员 → 优惠券 → [会员体系](./会员体系模块.md)、[优惠券](./优惠券模块.md)
6. Issue 问题清单逐项（定制入口、分类预设、百科内容增强等）
7. 微信支付、节日主题大模块等单独开 Issue → [微信支付](./微信支付模块.md)

- **0.2.0 改号前**不追求 Issue 清单全量复测（避免图片污染类回归拖死进度）；做**短回归**即可。
- 支付、会员**不挡** 0.2.0 改号。
