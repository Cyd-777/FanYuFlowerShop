# 版本与发版模块

> **分层**：工程  
> **归档来源**：`待处理/versions/` · `待处理/closed-loop-plan.md` · `待处理/post-closed-loop-branches.md`

## 策略

定义**几.x 必须完成什么才改号**，以及闭环之后的推荐推进顺序，避免版本号与能力范围脱节。

### 版本线

| 阶段 | 目标 | 策略要点 |
|------|------|----------|
| **0.1.x（当前）** | 把微商**三环闭环**做稳 | 商家维护商品 → 顾客下单 → 商家履约；**不含**微信支付、会员 |
| **0.2.0** | 闭环验收通过才改号 | 不挡改号项：支付、会员 |
| **0.2.x（闭环之后）** | 在闭环基础上**加固** | 搜索统一、智库升级、商品管理优化等 |
| **0.3.0 及以后** | 会员、优惠券等 | 仍不要求接入微信支付 |

### 闭环之后推荐优先级（与 Issue #1 对齐）

1. 合并闭环分支，打 **0.2.0** 标签（短回归）。
2. **搜索 + 智库契约**（可与 0.2.x 小版本同行）→ [搜索](./搜索模块.md)、[智库](./智库模块.md)
3. **分类管理优化**（按单位自动拆分）→ [分类管理](./分类管理模块.md)
4. 商品递交方式（自提 / 配送）、商品管理体验优化 → [订单](./订单模块.md)、[商品](./商品模块.md)
5. 会员 → 优惠券 → [会员体系](./会员体系模块.md)、[优惠券](./优惠券模块.md)
6. Issue 问题清单逐项（定制入口、分类预设、百科内容增强等）
7. 微信支付、节日主题大模块等单独开 Issue → [微信支付](./微信支付模块.md)

- **0.2.0 改号前**不追求 Issue 清单全量复测（避免图片污染类回归拖死进度）；做**短回归**即可。
- 支付、会员**不挡** 0.2.0 改号。

## 版本历史

### 0.1.x — 当前版本线

`package.json` 现为 `0.1.4`；Git 标签 `v0.1.0`。

**核心定位**：能上架、能逛、能装店。三环经营闭环（下单 → 商家接单 → 完成）属于向 0.2.0 推进的工作，在改号之前仍视为 0.1.x 时期的开发。

**0.1.x 已具备**：

- **身份与登录** — 微信一键登录、OpenID、商家/顾客角色、按角色跳转；身份码展示与复制
- **商家端** — 工作台、`initDb`、店铺设置、销售策略/主题装潢
- **商品管理** — 分类 CRUD、商品 CRUD、花卉选品、上下架/推荐、可售数维护；批量删除/上下架/推荐；进货单式批量加可售数；口语化范围搜索
- **顾客端** — 首页/分类/商品列表/详情、加购/购物车/去结算、定制花束、收藏、下单确认/订单列表/详情、地址管理（云函数）、百科 Tab/详情
- **智库** — 百科 Tab、详情、字典式搜索、标签交叉筛选、智能粘贴、笔记式行内编辑、商品关联、玫瑰养护试点
- **类 OA 通知** — 消息中心、订阅消息（3 模板）、订单/库存事件发通知
- **基础设施** — SWR 缓存、APP 内下载、多端分发规划、扫码核销

### 0.2.0 — 发版目标

**何时算达成**：下方条件全部完成后，将 `package.json` 定为 `0.2.0` 并打标签 `v0.2.0`。

**目标能力**：跑通三环——① 商家维护商品 → ② 顾客浏览并下单 → ③ 商家接单并完成（线下收款；无支付、无会员）。

**发版后 0.2.0 应包含**：

- **订单（三环核心）** — 确认页提交、列表/详情、待处理可取消；商家接单、完成、工作台统计；云函数 `order` 含创建/扣可售数/状态流转/快照；定制花束经购物车进入确认页
- **地址** — 云函数 `address`、微信导入、确认页选地址
- **商品管理（一阶段）** — 批量操作、进货单加可售数、口语搜索、销售标签
- **顾客看图** — 商品图对顾客可见（换链/代理）

**0.2.0 不含**：微信支付、会员、身份码二维码（三者均不挡改号）。

### 0.3.0 — 会员与优惠（拟定）

**状态**：未开始。0.2.0 改号完成后再规划。

**计划包含**：会员中心、等级、积分、签到（页面骨架已有）、优惠券/会员价与下单确认页衔接、与销售策略统一规则。

**不含**：微信支付、自提/配送选型、WMS/采购。

## 闭环实施记录（历史）

> 基础三环 6 步计划已完成。保留本文档作「为什么这样设计订单状态」的依据。

**已拍板约定**：

| 项 | 决策 |
|----|------|
| 付款 | 本阶段不接入微信支付；订单创建即「待处理」，由商家线下收款 |
| 库存 | 创建订单时服务端扣减；取消订单时回滚库存 |
| 完成方式 | 商家在订单详情点击「完成」；暂不强制顾客「确认收货」 |
| 地址 | 本地地址簿；写入订单快照（姓名、电话、地址文本） |
| 定制花束 | 与普通商品一样经购物车 → 确认页提交；行项目带 `customSummary` |

**订单状态（最小状态机）**：

```text
pending（待处理）→ processing（处理中）→ completed（已完成）
        ↘ cancelled（已取消）
```
