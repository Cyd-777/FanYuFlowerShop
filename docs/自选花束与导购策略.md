# 自选花束与导购 · 产品策略

> **关联**：§7.2 AI 导管 · §7.1 智库 · 自选花束项目  
> **更新**：2026-07-07

---

## 核心概念

**导购和自选本质是一种功能**，都是"帮用户找到想要的"，只是入口和用户心智不同。

---

## 用户场景

### 场景 A：有明确目标
> 用户想包一束**百合花束**，但不知道怎么配

- 用户进入**自选**
- 选主花（百合）
- 系统根据**智库词条**推荐搭配的配花、配叶
- 用户感知是自己挑的，实际推荐引擎在背后推

### 场景 B：有包花意向但无目标
> 用户想「自己包一束花」，但不知道用什么花

- 用户进入**自选**
- 走导购式短表单：送谁？什么场合？预算？
- 推荐四类花材（主花/点缀/配叶/…，用专用命名）
- 用户自由调整

### 场景 C：选择困难（花束样式过多）
> 店里花束样式很多，用户不确定该**买现成的**还是**自己包**

- 用户进入**自选**
- **不代表用户决定要自选**——可能只是想看看有什么
- 导购流程需要同时涵盖**单支花材 + 成品花束**
- 表单中设选项，用户不确定/未选的话，**单支和花束一起出**

---

## 导购表单设计要点

- 场景导向：送谁 / 场合 / 预算
- 可选是否倾向成品花束
- 未选择倾向 → 推荐混合结果（成品花束 + 花材搭配方案）
- **禁止长表单**：分段短表单，每步只问一个问题，逐步缩小范围
- 步数控制在 3–5 步，每步用户只需点选，无需输入

## 与智库 / AI 导管的关系

```
智库（品种/搭配/养护数据）
    │
    ├── 端侧向量模型（用户侧）
    │   ├── 花材匹配与搭配推荐
    │   ├── 语义搜索（花语/场景/品种）
    │   └── 实时响应，离线可用
    │
    └── 云端大模型（商家侧 + 端侧兜底）
        ├── 智库词条文案生成
        ├── 导购推荐文案润色
        ├── 搭配理由生成
        └── 端侧覆盖不到时的兜底
```

## AI 接入架构

```
┌──────────────────────────────────────────────┐
│                  前端                          │
│  recommend(mode, input) → Promise<Result>     │
│       │                                       │
│       ├── 端侧向量模型（优先）                  │
│       │   └── 匹配失败 / 置信度低 → 走云端       │
│       └── 云端大模型（兜底）                    │
│           └── wx.cloud.extend.AI               │
└──────────────────────────────────────────────┘
```

## 模型分工

| 侧 | 用途 | 模型类型 | 调用方 |
|----|------|---------|--------|
| **端侧** | 花材匹配、搭配推荐、语义搜索 | 向量模型（ONNX） | 顾客（导购/自选） |
| **云端** | 文案生成、百科描述、搭配理由 | DeepSeek/混元（LLM） | 商家（智库维护）+ 端侧兜底 |
```

## 关键原则

- AI 推荐是**隐式的**，用户感知上在自主挑选
- 自选入口不预设用户意图，可以导向成品花束
- 四类花材用**专用命名**（不使用"君臣佐使"技术用语）
