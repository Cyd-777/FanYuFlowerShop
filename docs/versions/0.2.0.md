# 0.2.0 — 发版目标（三环闭环）

**文档性质**：**发版目标说明**，不是「当前版本号」  
**当前版本线**：[0.1.x](./0.1.0.md)（尚未改号）  
**何时算达成**：下方「发版条件」全部完成后，将 `package.json` 定为 `0.2.0` 并打标签 `v0.2.0`  
**目标能力**：跑通三环——① 商家维护商品 → ② 顾客浏览并下单 → ③ 商家接单并完成（线下收款；**无支付、无会员**）

---

## 与当前阶段的关系

- 现在仍在 **0.1.x**，分支上的订单 / 地址等开发属于**推进工作**，不是「已经在做 0.2.0 版本号」
- 本文档列出：**从 0.1.x 推进到 0.2.0 必须做完什么**，做完才改号
- 会员 / 优惠券 → [0.3.0](./0.3.0.md)；支付 → 主体 AppID 待定，不纳入本目标

---

## 发版后 0.2.0 应包含

### 订单（三环核心）

- 顾客：确认页提交、订单列表 / 详情、待处理可取消
- 商家：订单列表 / 详情、接单、完成、工作台统计
- 云函数 `order`：创建、扣 / 回滚可售数、状态流转、快照
- 定制花束经购物车进入确认页

### 地址

- 云函数 `address`、微信导入、确认页选地址

### 商品管理（商家 · 第一阶段，随 0.2.0 一并交付）

- 批量操作、进货单加可售数、口语搜索、销售标签
- 云 `goods`：`batchUpdate`、`batchRemove`、`stockIn`、`publicImage`

### 顾客看图

- 商品图对顾客可见（换链 / 代理）

---

## 发版条件（0.1.x → 0.2.0，全部勾选才改号）

- [ ] 推进中的代码合并进 `main`，工作区干净
- [ ] 云函数 `order`、`address`、更新后的 `goods` 已部署到目标环境
- [ ] **链路 1**：商家建品 / 改可售数 / 上下架
- [ ] **链路 2**：顾客浏览 → 加购 → 选地址 → 提交订单
- [ ] **链路 3**：商家接单 → 完成；待处理取消测库存回滚
- [ ] 定制花束、收藏加购建议各测一条
- [ ] `package.json` → `0.2.0`，[0.1.0.md](./0.1.0.md) / 本文档更新状态，打 `v0.2.0`

**不挡改号**：支付、会员、顾客端改价后是否自动刷新列表。

---

## 发版后仍不做

- **微信支付** — 正式版小程序 ID（个体工商户 vs 个人）未确定，整体延后
- **会员 / 积分 / 优惠券** — [0.3.0](./0.3.0.md)
- 完整扫码核销、自提 / 配送选型、WMS

---

## 验收要点（改号前最后一轮）

### 商家

- 口语搜索、批量、进货单、订单接单 → 完成

### 顾客

- 看图、加购、下单、订单与取消规则、售罄 / 即将售罄角标

---

## 已知限制（允许随 0.2.0 发布）

- 支付：线下收款，订单为待处理
- 会员：无
- 顾客端列表：改价 / 改库存后可能需要重新进页或下拉刷新
- 批量改价弹层：未恢复

## 升级说明

- 须部署 `order`、`address`、新版 `goods`
- 旧本地地址不自动迁移，顾客需重新添加或微信导入
