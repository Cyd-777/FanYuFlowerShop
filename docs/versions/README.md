# 版本文档

每个 **minor 版本**对应一份说明文档。`0.1.0.md` 描述 **0.1.x 版本线**；`0.2.0.md` 描述**发版目标**（做到什么程度才能把版本号定为 0.2.0），不是「当前已经在做的版本号」。

## 当前 vs 目标

- **当前版本线**：**0.1.x**（`package.json` 现为 `0.1.4`；Git 有标签 `v0.1.0`）
- **推进目标**：**0.2.0** — 三环闭环发版条件见 [0.2.0.md](./0.2.0.md)
- **关系**：分支上可能在开发订单、地址等能力，但在 checklist 全部完成、正式改号发版之前，**版本号仍属 0.1.x**，不算「已经是 0.2.0」

```text
0.1.x（现在）  ──必做项做完、发版──▶  0.2.0（目标）
                                      │
                                      └──▶  0.3.0（会员/优惠，更后）
```

## 版本线（语义）

- **0.1.x** — 能上架、能逛、能装店；**当前所处阶段**
- **0.2.x** — 三环闭环（维护商品 → 下单 → 履约）；**尚未发版，仅为目标**
- **0.3.x** — 会员 / 积分 / 优惠券（销售策略；仍可不接支付）
- **支付** — 待定：正式版 AppID（个体工商户 vs 个人）确定后再规划

## 文档列表

- [0.1.0.md](./0.1.0.md) — **0.1.x 版本线**（当前）：已发布能力与范围
- [0.2.0.md](./0.2.0.md) — **发版目标**：推进到 0.2.0 必须完成的事项与验收
- [0.3.0.md](./0.3.0.md) — **更后目标**：会员与优惠（0.2.0 之后才考虑）
