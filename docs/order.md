# 订单模块

> **状态：搁置**  
> 付款方式尚未确定，暂不实现提交订单与支付。商品侧购物车、加购可继续使用；「去结算」跳转的确认页保持骨架，待付款方案明确后再启动本模块。

## 边界定义

**订单模块**从顾客进入**下单确认页（填单）**开始，覆盖核对商品、选地址/备注、提交订单、支付、订单查询与商家侧处理。

```text
购物车点击「结算」/ 详情「立即购买」
        ↓
确认页填单（地址、备注、核对）→ 点击「提交订单」→ 创建订单 → 支付 → 列表/详情 → 商家处理 → 核销
        ↑
   订单模块从此开始
```

浏览、加购、购物车管理归属 **[商品模块](./goods.md)**。

## 与商品模块的接口约定

| 时点 | 商品模块 | 订单模块 |
|------|----------|----------|
| 加购 / 改购物车 | 写入 cart，含 `goodsId`、数量、**服务端校验后的快照价** | — |
| 进入确认页 | 跳转；`checkedItems` 已在 cart store | 读 cart、展示填单 UI |
| 点击提交 | — | 终态校验、写库、扣库存、返回 `orderId` |
| 提交成功后 | 清空已下单的购物车项（由订单页/服务触发） | 负责后续状态与展示 |

**原则**：商品模块负责「想买什么」；订单模块负责「填单、买成了什么」及之后的一切。
