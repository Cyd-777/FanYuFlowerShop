# 订单模块

> **状态：基础三环闭环已完成**（无微信支付）  
> 详见 [closed-loop-plan.md](./closed-loop-plan.md)。

## 边界定义

**订单模块**从顾客进入**下单确认页（填单）**开始，覆盖核对商品、选地址/备注、提交订单、订单查询与商家侧处理、完成。

```text
购物车点击「结算」/ 定制花束预览提交
        ↓
确认页填单 → 提交订单 → 创建订单（扣库存）
        ↓
顾客订单列表/详情（可取消·仅待处理）    商家工作台/列表/详情 → 接单 → 完成
```

浏览、加购、购物车管理归属 **[商品模块](./goods.md)**。

## 订单状态与步骤条

详情页步骤条分 **门店**、**配送** 两段，对应完整履约流程：

```text
门店：待处理 → 已接单 → 订单处理中 → 制作完成
配送：等待骑手 → 已取货 → 在路上 → 已送达（完成后订单结束）
```

### 门店状态 `status`

| 状态 | 说明 | 触发方式 |
|------|------|----------|
| `pending` | 待处理（顾客**可取消**） | 顾客提交订单 |
| `accepted` | 已接单 | 商家点击「接单」 |
| `preparing` | 订单处理中 | 店员点击「确认订单信息」；**同步呼叫骑手** |
| `prep_done` | 制作完成 | 店员点击「制作完成」 |
| `completed` | 已完成 | 骑手**已送达**（`riderStatus=delivered`） |
| `cancelled` | 已取消（库存回滚） | 顾客（仅 pending）或商家 |

旧数据 `processing` 读取时归一为 `preparing`。

### 配送状态 `riderStatus`

| 状态 | 说明 |
|------|------|
| `none` | 尚未进入配送阶段 |
| `waiting` | 等待骑手（进入「订单处理中」时自动设置并呼叫） |
| `picked_up` | 已取货 |
| `on_way` | 在路上 |
| `delivered` | 已送达 → 订单 `completed` |

配送进度后续由配送平台回调更新；当前商家端提供人工推进按钮便于联调。

### 列表 Tab「处理中」

包含 `accepted`、`preparing`、`prep_done`（及旧版 `processing`）。

## 工作台统计口径

| 指标 | 计算方式 |
|------|----------|
| 今日订单 | 北京时间当日创建的订单数（含已取消） |
| 待处理 | 当前 `status=pending` 订单总数 |
| 今日收入 | 北京时间当日 **已完成** 订单的 `totalAmount` 合计 |

## 与商品模块的接口

| 时点 | 商品模块 | 订单模块 |
|------|----------|----------|
| 加购 / 改购物车 | 写入 cart | — |
| 点击提交 | — | 校验、写库、扣库存 |
| 提交成功 | `removeChecked()` | 跳转详情 |
| 取消订单 | — | 回滚库存、`status=cancelled` |

**原则**：商品模块负责「想买什么」；订单模块负责「买成了什么」及商家履约。
