# 搜索模块

> **分层**：附加  
> **状态**：已迁入策略

## 策略

统一**搜索框外壳**，按使用位置切换**三套词典**（商家商品 / 顾客商品 / 智库），并渐进支持顾客联合搜索与 AI 预判。

### 现状

- 商家商品管理：口语范围搜索较强（上架、推荐、价格等）。
- 顾客分类 / 商品列表： mainly 按**商品名称**搜。
- 百科 Tab：独立输入框，云端按 preview 文字子串匹配，最弱。
- 三套**未统一**搜索框组件与词典。

### 词典分工

| 搜索入口 | 负责范围 | 词典 |
|----------|----------|------|
| 商家商品管理 | 仅商家自己的商品 | 商家口语词典 |
| 百科 Tab | 仅智库词条 | 智库词典 |
| 分类 / 商品列表（及未来首页） | 商品；未来首页还要**联合**智库 | 顾客商品词典；首页另加「联合编排」 |

### 与智库关系

- **不要**让搜索模块去适配「旧智库」（preview 整段子串）作为长期方案。
- **要**先定「智库查询请求」的结构约定，搜索只负责产出该结构；智库云端自己决定怎么查库。
- **混合推进**（见下文），不是「智库 2.0 全部做完再搜索」。

### 混合推进步骤

**步骤 1 · 钉契约（优先）**

- 定义「智库查询请求」：原文、分词、当前 Tab、标签、花材编号、来源（手输 / 识图 / AI）等。
- 云端智库增加**结构化搜索**入口；保留旧「只传关键词」薄封装。
- **商品详情按花材匹配**不改行为。

**步骤 2 · 并行两线**

- **线 A · 搜索**：统一搜索框；商家 / 顾客 / 百科词典切换；百科 Tab 改用新智库搜索入口。
- **线 B · 智库数据**：补可搜索正文、标签、节日场景等字段（见 [智库](./智库模块.md)）。

**步骤 3 · 稍后**

- [顾客联合搜索](./搜索模块-顾客联合搜索.md)
- [类 OA 进货提醒](./类OA通知模块.md)（与搜索 UI 无关）
- [识图入智库](./AI导管模块-识图入智库.md)

- AI **不替代**搜索框 UI，只增强「解析与预判」→ [AI导管](./AI导管模块.md)。
- 识图进智库不走搜索框，走相机 → AI 导管 → 同一套智库查询约定。
