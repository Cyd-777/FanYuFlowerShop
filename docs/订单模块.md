# 订单模块

> **分层**：业务  
> **状态**：已迁入（源自 [待处理/order.md](./待处理模块-order.md)）

## 策略

订单模块从顾客进入**下单确认页（填单）**开始，覆盖核对商品、选地址 / 备注、提交订单、订单查询与商家侧处理、完成。

```text
购物车点击「结算」/ 定制花束预览提交
        ↓
确认页填单 → 提交订单 → 创建订单（扣库存）
        ↓
顾客订单列表/详情（可取消·仅待处理）    商家工作台/列表/详情 → 接单 → 完成
```

负责「买成了什么」及商家履约；浏览、加购、购物车管理归属 [商品模块](./商品模块.md)。

**当前状态**：基础三环闭环已完成（无微信支付）。历史分步计划见 [待处理/closed-loop-plan.md](./待处理模块-closed-loop-plan.md)。

**递交与支付**：自提 / 配送选型（`feat/order-delivery`）为闭环之上增强 → [履约规则](./订单模块-履约规则.md)、[待处理/post-closed-loop-branches.md](./待处理模块-post-closed-loop-branches.md)。**微信支付**、第三方配送**刻意后置** → [微信支付](./微信支付模块.md)、[第三方配送](./第三方配送模块.md)。过渡期「联系客服下单」→ [店铺设置 · 客服下单开关](./店铺设置模块-客服下单开关.md)。

- 浏览、加购、购物车 → [商品模块](./商品模块.md)
- **微信支付**、第三方配送 → 刻意后置（[微信支付](./微信支付模块.md)、[第三方配送](./第三方配送模块.md)）
- **扫码核销** → 本阶段暂停（[扫码核销](./订单模块-扫码核销.md)）
- 地址簿长期 CRUD 的完整产品定义 → [地址](./地址模块.md)（确认页仅消费快照）

## 与商品模块的接口

| 时点 | 商品模块 | 订单模块 |
|------|----------|----------|
| 加购 / 改购物车 | 写入 cart | — |
| 点击提交 | — | 校验、写库、扣库存 |
| 提交成功 | `removeChecked()` | 跳转详情 |
| 取消订单 | — | 回滚库存、`status=cancelled` |
